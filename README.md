# webOS Homebrew Repository

Публичный каталог IPK для Homebrew Channel: <https://atlet99.github.io/webos-repos/>.

## Подключение на телевизоре

В Homebrew Channel откройте **Settings → Add repository** и добавьте:

```text
https://atlet99.github.io/webos-repos/apps.json
```

## Собственные IPK

1. Положите IPK в `packages/`. Для обновления удалите прежний IPK этого приложения и добавьте новый: на один ID допускается один пакет.
2. При необходимости настройте `rootRequired`, `shortDescription` и `sourceUrl` для ID приложения в `packages.json`. Для приложения, которому нужен root, обязательно укажите `"rootRequired": true`.
3. Если у приложения нет описания, создайте `descriptions/<id>.html` по шаблону `descriptions/_template.html`. Имя файла — ID из `appinfo.json`, а не имя IPK. При замене IPK файл сохраняется.
4. Выполните `make build`. Нужны Python 3 и утилита `ar`; зависимости устанавливать не требуется.
5. Закоммитьте IPK, описание и изменения конфигурации и отправьте их в `main`.

Сборка читает `appinfo.json` и значок из IPK, вычисляет SHA-256 и размер, затем создаёт страницу, `apps.json`, манифесты и `SHA256SUMS` в `_site/`. В `SHA256SUMS` входят только локальные IPK. Результат сборки в Git не добавляется. Для проверки выполните `make test`.

`make` или `make help` показывает список команд из описаний в Makefile. `make check` запускает тесты и проверку Makefile через установленный `checkmake` с настройками из `checkmake.ini`; `make clean` удаляет результат сборки. Другой интерпретатор можно выбрать через `make build PYTHON=python3`.

## Внешние репозитории

Добавьте HTTPS-адреса каталогов `apps.json` в массив `repositories.json`. При сборке приложения со всех страниц каждого каталога объединяются с локальными. Манифесты, ссылки на IPK, значки и описания сохраняют адреса источника; сами внешние IPK не копируются. Если источник недоступен, некорректен или содержит ID, уже встречающийся в другом источнике либо среди локальных IPK, сборка завершается с ошибкой и опубликованная версия остаётся прежней.

## Описания для Homebrew Channel

Homebrew Channel показывает HTML из `fullDescriptionUrl`, а при его отсутствии — `shortDescription`. Если описание уже есть в каталоге, `packages.json` или `appinfo.json`, отдельный файл не обязателен. Иначе сборка сообщит, какой файл `descriptions/<id>.html` необходимо создать. Сборка не задаёт интерактивных вопросов, чтобы её можно было запускать в GitHub Actions.

Можно также создать такой файл для приложения из внешнего каталога: он заменит полное описание источника в нашем каталоге. Пишите HTML-фрагмент в UTF-8, например `<p>Описание</p><ul><li>Возможность</li></ul>`. Homebrew Channel очищает HTML и удаляет, в частности, стили, формы и скрипты. Файл публикуется по `fullDescriptionUrl`, короткое описание при необходимости формируется из его текста.

## Публикация

В настройках GitHub откройте **Settings → Pages** и выберите **GitHub Actions** как источник. Workflow публикует изменения после push в `main`, раз в сутки обновляет внешние каталоги и доступен для ручного запуска. Внешние обновления появляются после очередной успешной сборки. Отдельная ветка `gh-pages` не нужна: GitHub Pages получает собранный артефакт напрямую.

При другом адресе сайта задайте `BASE_URL` при сборке и в workflow; URL должен быть HTTPS и не содержать завершающий `/apps.json`.
